# V5.4 后端持久化与安全启动

后端使用管理员已创建的 posture_event 表，前端展示状态变化历史。
启动流程不修改 MySQL 表结构或账号权限，也不修改 BearPi 固件。

## 已实现

- JPA 与 MySQL JDBC 依赖保留，Web、WebSocket、Paho、测试依赖保留。
- 数据库账号 `posture_app`，密码来自 `DB_PASSWORD`；`ddl-auto: validate`，只校验表结构。
- `DeviceStateService` 比较收到的新旧 `state` 与 `armed`，首次上报和任意一个字段变化时创建事件快照。
- 首次 `previousState` 为 null；之后记录前一条收到的设备状态，即使那一条曾写库失败。
- 连续同状态心跳只刷新实时状态/WebSocket，不入库、不进入写库队列。
- 快照包含 XYZ、base、change、温度、布防状态，时间使用后端接收时间，UTC、微秒精度。
- 使用单线程有界队列异步写库，容量 256。队列满或数据库异常会记录未保存日志，实时推送继续。
- 没有持久重试队列；故障期间或进程强制退出时可能丢失事件。相同状态的后续心跳不会重试入库。

## 启动（Windows + WSL）

前提：Windows 上的 MySQL 与 Mosquitto 已按项目现有配置运行；
MySQL 的 posture_monitor 数据库、posture_event 表及 posture_app 账号已准备好。
本流程不修改账号权限、表结构或 Windows/WSL 网络设置。

1. 在 Windows 启动现有 MySQL 服务和使用现有配置的 Mosquitto。
   保持现有 3306/1883 连接方式，不需要重新安装或开放新的端口。
2. WSL 需要 Java 17 和 Maven。首次使用先在 backend 目录执行 mvn package，
   下载依赖并运行默认 H2 测试，不需要输入生产数据库密码。
3. 确认没有另一个后端占用 8080，避免重复使用同一个 MQTT client-id，然后运行：

```bash
cd ~/workspace/bearpi-hm_nano/dashboard/backend
bash start-backend.sh
```

等 MySQL password 提示出现后再输入正确密码，不要把密码写到命令里。
Java Console 隐藏输入先用于 JDBC 登录校验，再通过 Maven 子进程的
DB_PASSWORD 环境变量传给 Spring Boot。无需手动 read/export；
脚本会忽略原终端中的旧 DB_PASSWORD，不保存密码，不改动原终端环境。
脚本也清除 JAVA_TOOL_OPTIONS、JDK_JAVA_OPTIONS 和 _JAVA_OPTIONS，
与已经验证的诊断启动流程一致；pom.xml 的 IPv4 JVM 配置仍生效。
保持终端运行，使用 Ctrl+C 停止后端。

启动路径由 start-backend.sh 自身位置确定，不依赖用户名或仓库克隆目录。
默认使用 Maven 标准缓存中的 Connector/J 9.1.0；
自定义缓存或驱动升级时，可将 MYSQL_CONNECTOR_JAR 设置为实际 JAR 文件路径
（这不是密码变量）。缺少驱动时脚本会停止并提示先准备依赖。

Vue3 前端在另一个 WSL 终端启动：

```bash
cd ~/workspace/bearpi-hm_nano/dashboard/frontend
npm ci
npm run dev
```

打开 http://localhost:5173/。Vite 将 /api 和 /ws 代理到后端 8080。
页面包含实时状态、三轴曲线、冲击提示以及最近最多 100 条历史事件；
历史统计仅针对已加载记录，不代表数据库全部记录。

## 历史接口

```bash
curl --noproxy '*' -s 'http://127.0.0.1:8080/api/device/events?limit=20'
```

返回 JSON 数组；空表为 `[]`。默认 limit=20，允许 1–100，非法参数返回 400。
按 receivedAt 倒序、id 倒序排列。数据库不可用时返回 503。
每条记录含 `id, previousState, state, armed, x, y, z, base, change, temperature, receivedAt`。
原有 `/api/device/status` 和 `/ws/device` 保留。

## 测试与验收

`mvn clean package` 默认只使用 H2 内存测试库，不接触 MySQL 或 MQTT。
真实 MySQL 测试设置 `TEST_DB_URL`、`TEST_DB_DRIVER=com.mysql.cj.jdbc.Driver`、`TEST_DB_USERNAME`、`TEST_DB_PASSWORD`、`TEST_SQL_INIT=never` 后执行 `mvn test`。
测试中的 Hibernate 同样使用 validate；SQL 初始化仅用于默认 H2 测试库。
仅对空的开发/测试事件表执行真实数据库这组测试（断言依赖空表）。测试记录自动回滚，不要求 DELETE 权限；自增 ID 的消耗不会回滚。

自动测试覆盖首次上报、六次状态/布防变化、连续十条同状态心跳、previousState 链、真实数据库时间往返、limit 数组接口和非法参数、数据库异常、异步写入阻塞时实时推送继续。

实际硬件最后验收：启动后让 BearPi 依次触发 NORMAL、MOVING、TILT、IMPACT，再查询历史。持续同状态心跳不应增加条数。
V5.4.3 历史列表在 Vue3 Dashboard 中展示；筛选及 IMPACT 统计均限于已加载的最近最多 100 条记录。
